# Live experiment analysis (not the team report)

Both versions now contain 50 unique trials on the identical case/trial pairs, using openai/gpt-4o-mini. All 100 records contain API usage. Frozen scaffold and data hashes match the manifest. Previously archived 30 local encoding failures are excluded from the active results, not erased from the audit trail.

| Metric | v1 | v2 |
|---|---:|---:|
| Code-check pass | 10/50 (20%) | 4/50 (8%) |
| Input tokens | 490,509 | 508,115 |
| Output tokens | 14,351 | 14,601 |
| Total tokens | 504,860 | 522,716 |
| Standard-price calculated USD cost | 0.082185 | 0.084975 |
| Median recorded tool-loop turns | 3.5 | 5 |
| Persisted simulated bookings | 0 | 0 |
| Missing-evidence guardrail stops | 7 | 24 |
| Illegal-slot guardrail stops | 11 | 1 |

Observed code-check pass fell by 12 percentage points; total API tokens increased 3.54%, calculated cost increased 3.39%. This single battery does not show an improvement from v2, and does not establish a universal ranking or statistical significance. Cost is calculated from recorded tokens at the manifest list prices, not the provider invoice; interrupted requests may have unrecorded billing.

The central operational failure is that neither version executed any booking, including the 20 trials expected to book. v2 frequently tried booking without first completing lookup_patient. Both versions also produced missing/wrong structured trigger fields and incomplete missing-test fields. These are distinct from prose quality. Fewer illegal-slot stops in v2 cannot establish safer slot choice because an earlier missing-evidence gate can stop execution before slot validation.

Guardrail blocking is evidence of prevented actions, not successful completion of the referral task, and not proof that all hostile inputs are handled. Do not remove required safety checks merely to raise pass rates.

Judgement checks remain pending; code pass is not overall pass. Local per-tool return token measurement also remains pending because tiktoken is unavailable in this runtime. API input/output token totals above are available and valid; these are a different metric from tokens per tool return.

Next: preserve this battery as the measured v1/v2 result; complete semantic grading and return-size token measurement; investigate shared prompt/output contract and lookup ordering before asking teammates to run more models. If shared code/prompt is revised, label it as a new experimental revision and rerun both versions for a fair new comparison. No additional model calls were made during this analysis.
